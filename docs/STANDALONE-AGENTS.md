# Standalone Agent development

[English](STANDALONE-AGENTS.md) | [简体中文](STANDALONE-AGENTS.zh-CN.md)

`ergo-agent new` scaffolds an independently runnable Sub or Meta Agent. The
generated application imports the minimal `github.com/ageniti/ergo-core/runtime`
package, embeds only its own `resources/` directory, and always passes an
explicit `agentId`. It does not import the SDK's bundled Chief/default resource
package.

Install the command:

```bash
go install github.com/ageniti/ergo-agent/cmd/ergo-agent@latest
```

Installing the CLI this way downloads the complete `ergo-agent` source Module
once. Projects generated by the CLI depend only on `ergo-core`. A prebuilt CLI
release avoids the source installation download when one is available.

## Generate an independent Go program

```bash
ergo-agent new \
  --name reviewer-agent \
  --role meta \
  --module example.com/reviewer-agent

cd reviewer-agent
go mod tidy
OPENAI_API_KEY=... go run . "Review this repository."
```

The output is intentionally small:

```text
reviewer-agent/
├── go.mod
├── main.go
├── README.md
├── README.zh-CN.md
└── resources/
    ├── package.json
    ├── agents/reviewer-agent.md
    └── prompts/system/reviewer-agent.md
```

Building this directory creates one executable. The executable contains the
selected Agent profile and prompt, not the repository's Chief Agent resources.

## Generate only an installable Agent Package

```bash
ergo-agent new \
  --name reviewer-agent \
  --role meta \
  --package-only
```

This output has no `main.go` and no Runtime. It is a declarative Agent Package
for installation into an existing Ergo host.

## Dependencies

A freshly generated Agent has no Agent dependencies. Add delegation only when
the role permits it:

```yaml
role: sub
tools: read, grep, subagent
delegates: web-researcher
```

Then place the dependency's profile and system prompt in the same `resources/`
tree and list it in `package.json` under
`ergo.agentDependencies`. A Meta Agent cannot delegate. The package validator
rejects missing dependencies and role-incompatible delegation.

For an existing repository Agent whose dependencies are already declared, use
`cmd/agent-package`; it recursively collects and freezes the entry Agent's
declared dependency closure.

## Runtime choices

| Need | Import / command | Bundled Chief resources |
| --- | --- | --- |
| Only your own Agent(s) | `github.com/ageniti/ergo-core/runtime` | No |
| Ergo's complete default suite | `github.com/ageniti/ergo-agent/agent` + `agent.NewDefault()` | Yes |
| Resources for an existing host | `ergo-agent new --package-only` | No Runtime |

The execution engine is shared in all cases. The difference is only which
resources and default entry point are linked into the application.

`ergo-agent` is the only editable source repository. Its
`cmd/export-core` command produces the read-only `ageniti/ergo-core`
repository, and the release workflow publishes it after independent tests.
Developers who import `ergo-core` therefore do not download the complete
Agent suite.
